# Classic RPG interface

The interface uses an original window design inspired by classic Final Fantasy and Dragon Quest menus: cobalt blue, ivory double borders, pixel text and a decorative triangular cursor. It uses the existing Avelune artwork and gameplay.

Exploration keeps the map clear. **Command (C)** opens Characters, Items, Atlas, Journal, Magic and Town, with contextual shop shortcuts inside that window. **Characters (P)** opens the recruited party; selecting a hero opens their equipment, magic, fixed job and attack growth. Close with Escape or repeat C/P in the corresponding window. Optional panels start closed on new games, Continue and area changes. Party status remains visible during battles, where it informs command selection.

Each roster row displays the hero's job, level, HP and current/max MP with a blue mana bar. Low HP and fallen companions have distinct text colors. On small screens the roster uses two columns, with a lone hero spanning the window. Character tabs match the actual recruited party size. Current HP/MP refresh when opening the window after recovery or combat. A back action returns from character details to the overview. Jobs remain fixed.

Both field controls have 44px targets, announce whether their window is expanded and keep a stable keyboard focus destination. Dialogs pause movement, make the field inert and trap Tab inside the active window. Closing a nested tool returns focus to the visible field control that opened the flow. Command's displayed shortcuts also work while Command is open, with Town unavailable on roads that have no services.

Battles place commands to the left of party status, with enemy choices above and a message window below. Longer spell, item and targeting menus expand across the lower console on phones. The pixel battlefield keeps integer scaling. Shops and inns share framed selection lists, aligned prices, flat command tabs and the same cursor treatment. Status, equipment, spell preparation, journals, dialogue and the title screen share the window palette.

Arrow keys move focus through open menus; Enter activates a focused command and Escape closes the window. Walking remains available with arrows or WASD when menus close. Native select controls keep their normal keyboard behavior. Cursors use empty CSS shapes so screen readers receive the actual command name. Touch controls and primary menu actions use at least 44px targets.

`npm run test:menus` verifies default disclosure, repeated window switching, shortcut activation, live party values, focus, walking isolation, Continue, hostile areas and battle transitions at desktop, 390px and 320px widths. `npm run test:ui` checks title, exploration, status/jobs, purchases, field casting and battle commands at 1440×1000, 1280×900, 390×844 and 320×724. It verifies numeric status, modal focus, world input isolation, responsive bounds, touch sizes, integer battlefield pixels, spell targeting and browser/resource errors, and captures screenshots for visual inspection. The existing gameplay, services and travel browser suites remain the regression checks for transactions, combat, saves and overworld entry.

The field viewport now uses the space recovered from the persistent panels. Towns retain consistent integer pixel scaling indoors and outdoors; the overworld still reveals a wider area with miniature landmarks. The default field, Command and recruited-party windows were inspected at 1440px, 390px and 320px. Verification on 9 November 2026 passed all 97 Node tests and browser groups: 13 disclosure, 13 classic UI, 17 gameplay, 13 services, nine party/mana, nine recruitment, nine travel, six local rendering and four overworld rendering. Local rendering covered all 211 local/service scenes and 64 character poses. No browser exceptions or missing game resources were reported. The standalone edition also passed its menu flow with no external asset requests.
